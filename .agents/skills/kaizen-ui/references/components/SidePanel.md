# SidePanel

A dialog pinned to the left or right side of the screen that can be triggered by a button or other
element. Uses the native `<dialog>` element for progressive enhancement, providing built-in
backdrop styling, focus management, and support for `form method="dialog"` for native close behavior.

Use a side panel when you need to show supplementary content or actions while maintaining the
context of the main view. Side panels are ideal for tasks that require user input or displaying
additional information without navigating away from the current page.

Common use cases include:

- Displaying details about a selected item
- Forms that need context from the main view
- Configuration panels
- Multi-step workflows
- Preview panels

Consider a Modal instead when:

- The task requires full user attention and blocking interaction with the main content
- The content needs to be center-focused
- The interaction is brief and doesn't require context from the main view

## Examples

### Basic Side Panel

Use when you need to show supplementary content while maintaining context of the main view.

```tsx
<SidePanel
    slotTrigger={<Button>Open Panel</Button>}
    slotHeading="Details"
    slotFooter={
        <>
            <SidePanelCloseButton kind="tertiary">Cancel</SidePanelCloseButton>
            <Button color="brand">Save</Button>
        </>
    }
>
    Panel content with supplementary information.
</SidePanel>
```

### Modal Side Panel

Use when the side panel content requires focused attention and should block interaction with the main page.

```tsx
<SidePanel
    modal
    bordered
    slotTrigger={<Button>Open Modal Panel</Button>}
    slotHeading="Important Information"
    slotFooter={
        <>
            <SidePanelCloseButton kind="tertiary">Close</SidePanelCloseButton>
            <Button color="brand">Acknowledge</Button>
        </>
    }
>
    This panel requires focused attention with a backdrop overlay.
</SidePanel>
```

### Form Side Panel

Use when the side panel wraps a form that needs native form submission behavior.

```tsx
<SidePanel
    bordered
    slotTrigger={<Button>Open Form</Button>}
    slotHeading="Create Resource"
    renderContent={({ children }) => <form onSubmit={handleSubmit}>{children}</form>}
    slotFooter={
        <>
            <SidePanelCloseButton kind="tertiary">Cancel</SidePanelCloseButton>
            <Button type="submit" color="brand">
                Create
            </Button>
        </>
    }
>
    Form fields go here
</SidePanel>
```

### Custom Width Side Panel

Use when the default panel width is insufficient for the content being displayed.

```tsx
<SidePanel
    bordered
    slotTrigger={<Button>Open Wide Panel</Button>}
    slotHeading="Wide Panel"
    style={{ '--side-panel-width': '500px' }}
>
    This panel uses a custom width for content that needs more space.
</SidePanel>
```

### With Navigation Side Panel

Use when the panel needs tabs or breadcrumbs sitting between the heading and the main content.

```tsx
<SidePanel
    bordered
    slotTrigger={<Button>Open Panel</Button>}
    slotHeading="Architecture"
    slotNavigation={
        <Tabs
            defaultValue="layers"
            items={[
                { children: 'Layers', value: 'layers' },
                { children: 'Parameters', value: 'parameters' },
                { children: 'Performance', value: 'performance' }
            ]}
        />
    }
    slotFooter={
        <>
            <SidePanelCloseButton kind="tertiary">Cancel</SidePanelCloseButton>
            <Button color="brand">Save</Button>
        </>
    }
>
    Tab content rendered here.
</SidePanel>
```

### Relative Side Panel

Use when the panel should be confined to a parent region rather than overlaying the viewport. The parent must be `position: relative` with `overflow: hidden`.

```tsx
<div
    style={{
        position: 'relative',
        height: 400,
        width: 500,
        overflow: 'hidden',
        border: '1px dashed currentColor'
    }}
>
    <SidePanel relative slotTrigger={<Button>Open Panel</Button>} slotHeading="Cluster Status">
        Cluster monitoring and management.
    </SidePanel>
</div>
```

### Default Open Side Panel

Use when the panel's open state is driven by SSR or URL params — render with `defaultOpen` so the panel appears open on the first paint.

```tsx
<SidePanel
    defaultOpen
    bordered
    slotTrigger={<Button>Edit Task</Button>}
    slotHeading="Edit Task"
    slotFooter={
        <>
            <SidePanelCloseButton kind="tertiary">Cancel</SidePanelCloseButton>
            <Button color="brand">Save</Button>
        </>
    }
>
    Form fields go here.
</SidePanel>
```

### Anchor Trigger Side Panel

Use when the panel must open from a regular link for SSR-friendly, no-JS progressive enhancement. Requires `id` plus an `<a href='#id'>` passed via `slotAnchorTrigger`.

```tsx
<SidePanel
    id="settings-panel"
    bordered
    slotAnchorTrigger={<a href="#settings-panel">Open Settings</a>}
    slotHeading="Settings"
    slotFooter={<SidePanelCloseButton kind="tertiary">Close</SidePanelCloseButton>}
>
    Settings content here.
</SidePanel>
```

### Native Form Dialog Side Panel

Use when the panel hosts a server-action form and cancel must close without submitting. `formMethod="dialog"` lets the native dialog close without JavaScript.

```tsx
<SidePanel
    bordered
    slotTrigger={<Button>Edit Task</Button>}
    slotHeading="Edit Task"
    attributes={{
        SidePanelCloseButton: {
            type: 'submit',
            formMethod: 'dialog',
            formNoValidate: true
        }
    }}
    renderContent={({ children }) => (
        <form action="/api/update-task" method="post">
            {children}
        </form>
    )}
    slotFooter={
        <>
            <input type="hidden" name="taskId" value="123" />
            <Button type="submit" formMethod="dialog" formNoValidate kind="tertiary">
                Cancel
            </Button>
            <Button type="submit" color="brand">
                Save Changes
            </Button>
        </>
    }
>
    Form fields go here.
</SidePanel>
```

### Below App Bar Side Panel

Use when the page has a fixed AppBar — offset the panel by the AppBar height so it docks beneath the bar instead of overlapping it.

```tsx
<SidePanel
    bordered
    className="top-[var(--nv-app-bar-height)]"
    slotTrigger={<Button>Open Side Panel</Button>}
    slotHeading="Heading"
    slotFooter={<SidePanelCloseButton kind="tertiary">Close</SidePanelCloseButton>}
>
    Panel content sits below a fixed AppBar.
</SidePanel>
```

### Multi Step Side Panel

Use a multi-step pattern for wizards, guided flows, or any task that progresses through discrete stages. Track the current step in state and use `ml-auto` on the cancel button to push the primary action to the trailing edge.

```tsx
;() => {
    const [step, setStep] = useState(0)
    const totalSteps = 3
    const isFirstStep = step === 0
    const isLastStep = step === totalSteps - 1
    return (
        <SidePanel
            bordered
            slotTrigger={<Button>Open Side Panel</Button>}
            slotHeading={`Step ${step + 1} of ${totalSteps}`}
            slotFooter={
                <>
                    <Button
                        kind="secondary"
                        disabled={isFirstStep}
                        onClick={() => setStep(s => Math.max(0, s - 1))}
                    >
                        Back
                    </Button>
                    <SidePanelCloseButton className="ml-auto" kind="tertiary">
                        Cancel
                    </SidePanelCloseButton>
                    <Button
                        color="brand"
                        onClick={() => setStep(s => Math.min(totalSteps - 1, s + 1))}
                        disabled={isLastStep}
                    >
                        Next
                    </Button>
                </>
            }
        >
            <Flex direction="col" gap="2">
                Content for step {step + 1}.
            </Flex>
        </SidePanel>
    )
}
```

### Composed

Use composed primitives when you need full control over the side panel layout and behavior.

```tsx
<SidePanelRoot>
    <SidePanelTrigger asChild>
        <Button>Open Panel</Button>
    </SidePanelTrigger>
    <SidePanelContent bordered>
        <SidePanelHeading>Composed Heading</SidePanelHeading>
        <SidePanelMain>Composed side panel content using primitives directly.</SidePanelMain>
        <SidePanelFooter>
            <SidePanelCloseButton kind="tertiary">Cancel</SidePanelCloseButton>
            <Button color="brand">Save</Button>
        </SidePanelFooter>
    </SidePanelContent>
</SidePanelRoot>
```
